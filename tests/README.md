# 回归测试

一句话：**改任何规则/代码后，把下面三套测试都跑一遍，全绿再交付。**

改生成规则的风险不在"报错"，而在"静默改错"——程序段照样生成、照样能粘贴、编译也过，
但线号接错一个，到现场就是停线。快照回归比对的是**全部输出的内容**，不是代码覆盖率。

## 三套测试都要跑（同步 2026-11-15 通用识别后）

| 命令 | 覆盖 | 前置依赖 |
|---|---|---|
| `python -m pytest tests/ -q` | 通用识别、地址解析、成组交叉匹配、批量判断、剪贴板 XML、工作台接口（50 项） | `pip install -r requirements-dev.txt` |
| `node tests/test_workbench_review.js` | 前端批量选择/保存/重名拦截/300 行保存/部分失败（1 项） | Node.js，无 npm 依赖 |
| `python tests/regress.py --check` | 旧格式（legacy）全流程输出快照 | 只要 `requirements.txt` |

注意：

- `pytest` 不会收集 `regress.py`（文件名不以 `test_` 开头），更不会跑 `.js`，所以三条必须分别执行。
- **`regress.py` 直接调 `compare_io → generate_program → audit_program`，绕过了 `run_all.py` 的通用识别分流**，
  它只保护旧格式项目。通用识别流程目前只有 pytest 单元测试，没有端到端输出快照。
  等有真实通用格式项目后，应把用例改走 `run_all.py`（见下方「加真实用例」）。
- 实测基线：Python 3.13.14 / pymupdf 2.1 / openpyxl 3.1.5 / pytest 9.2.0 / Node 22.22.2，
  `pytest 50 passed`、JS `PASS`、快照 `--check` 全绿。

## 快照回归命令

```
python tests/regress.py --list            列出用例和期望结果状态
python tests/regress.py --check           校验全部用例（不通过退出码 1）
python tests/regress.py --check <用例>     只校验一个
python tests/regress.py --snapshot <用例>  确认改动是对的，用它更新期望结果
```

## 现有用例

| 用例 | 数据来源 | 覆盖 |
|---|---|---|
| `smoke` | 合成（我造的） | 从点表起的后三步：对点/生成/清算；覆盖 一致、程序缺少该点、原注释待启用、模拟量 |

`smoke` 只能证明**结果稳定**，不能证明**结果符合现场**。它的作用是：任何改动把既有输出搅乱了，
立刻能看见。

## 加真实用例（重要）

请提供一个**已经做过、结果已知**的老项目，脱敏后放进来：

```
tests/cases/<项目代号>/
  图纸.pdf                 新项目图纸（有它才覆盖 PDF 提取这一步）
  旧程序/
    <段名>.st.txt          原来的导出文件，直接拷进来
    variables.txt          可选
```

步骤：

1. 把上面两个东西拷进 `tests/cases/<项目代号>/`
2. `python tests/regress.py --snapshot <项目代号>` —— 记录「当前代码」在这个项目上的输出
3. **人工核对一遍**生成的 `对点报告.xlsx` 和 `新程序段/`，确认跟你当年交付的一致
   - 不一致的地方，如果是工具错了 → 改代码，重跑 `--snapshot`
   - 如果是当年的现场判断（工具本来就要人工判断）→ 保持现状即可，这类点会进「待判断.xlsx」
4. 核对通过后，这个用例就成了护城河：以后改规则跑 `--check`，它替你盯着

建议至少两个用例：一个**老的、复杂的**（覆盖作废页、A/B 对称、模块号带字母这些坑），
一个**刚做完的**（贴近现在的图纸风格）。

## 快照里有什么

`tests/golden/<用例>.txt` 是纯文本，把输出目录下每个文件序列化进去：

- `.xlsx` → 逐工作表、逐行、单元格用 ` | ` 连接（只比内容，不比颜色/列宽）
- `.csv` / `.txt` / `.bat` → 原文（自动识别 UTF-8 / GBK）
- `.html`、`.bin` 跳过（前者是 `.st.txt` 的重复展示，后者是二进制底稿）

绝对路径会替换成 `<OUT>` `<CASE>` `<IO>` `<ROOT>`，所以快照能跨机器比对。

## 已知局限

- 样式（单元格颜色、下拉框、列宽）不比对
- 工作台的后端接口与前端交互由 `test_workbench_*.py` / `test_workbench_review.js` 覆盖，但界面布局、配色仍需人工看
- `smoke` 是合成数据，它的"正确结果"没有现场含义，别拿它当业务正确性依据
